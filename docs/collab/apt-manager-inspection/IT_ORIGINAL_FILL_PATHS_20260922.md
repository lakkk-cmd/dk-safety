## 2. 현 구현이 CEO 기준과 어긋나는 이유

`src/lib/document-pdf.tsx` 흐름(실독):

1. `UnitInspectionElement` — React/CSS로 **별지15 유사 표**를 그림 (헤더 색, ResultCircle, 서명 2칸 재배치 등)
2. satori(`next/og`) → 세로 긴 PNG
3. pdf-lib로 A4 슬라이스 → PDF

즉 **원본 PDF/HWP 바이트를 불변 배경으로 쓰지 않습니다.**  
높이 수동 추정(`estimateHeightBeforeDiagnosisBlock` 등)으로 하단 「관리사무소」 잘림이 난 것도 이 재구성 경로의 증상입니다.

코드상 N/A는 이미 `checklistResultSymbol`에서 `"/"`로 매핑되어 있습니다. 다만 **이번 방문 샘플에는 `/` 셀이 없어** 육안 검증은 여전히 미완입니다. (이전 QA의 「해당없음」문자열 지적은 **현재 스니펫 기준으론 해소된 상태** — 재샘플에서 미방문 건으로 재확인 필요.)

## 3. 기술 경로 후보 (2~3) — 리스크·현실성

공통 전제: **1페이지 = 법정 별지15만**. AI 진단·실측/기준·권고는 **별첨 2페이지**(또는 별도 PDF)로 분리. 1페이지 레이아웃을 늘리거나 색/서명란을 바꾸지 않음.

### 후보 A — **불변 원본 PDF 배경 + 좌표 오버레이** (권고 1순위)

| 항목 | 내용 |
|------|------|
| 방법 | 고시 PDF(`원본_별지15_고시.pdf`)를 **템플릿으로 고정**. pdf-lib로 페이지를 복사한 뒤, 미리 측량한 좌표에만 ○·×·`/` · 호/귀하/일자 · 비고 · 「{아파트명} 관리사무소」 · 서명 이미지를 **스탬프** |
| 현실성 | **높음**. 스택이 이미 pdf-lib 사용. Linux 서버·CI에서도 동작. 한글/HWP 런타임 불필요 |
| 리스크 | 좌표 드리프트(프린터/해상도); 원본 폰트와 스탬프 폰트 이질감; 긴 비고가 셀을 넘치면 **원본 칸을 깨지 않도록** 잘라야 함; 템플릿 PDF 교체 시 좌표 재측량 |
| 완화 | A4 pt 단위로 셀 중심점 표(12칸)를 문서화; 스탬프 전용 글리프(○×/)만 임베드; 비고는 셀 bbox 클리핑 |
| CEO 0% 정합 | **배경·격자·고정문구는 원본 그대로** → 기준에 가장 가깝음. “채움”만 허용 해석과 일치 |

### 후보 B — **HWP 원본에 값 기입 → 한글/Hancom으로 PDF 내보내기**

| 항목 | 내용 |
|------|------|
| 방법 | `원본_세대점검표_CEO첨부.hwp`를 템플릿으로 두고, 누름틀/표 셀에 결과만 넣고 HWP→PDF |
| 현실성 | **낮~중**. 서버(Linux)에 한글 자동화 없음. Windows+한컴 API/매크로·또는 수동 내보내기에 의존. OLE BodyText 바이너리 직접 패치는 **깨짐 위험 큼**·비권장 |
| 리스크 | 운영 자동화 어려움; 라이선스·GUI 의존; 버전(HWP5) 호환; 장애 시 재현 비용 |
| 적합한 경우 | “법적 원본 파일 자체”를 보관·제출해야 할 때. 웹 대량 발급 메인 경로로는 부담 |

### 후보 C — **원본 PDF에 AcroForm을 1회 설계 후 필드 채움** (A의 변형)

| 항목 | 내용 |
|------|------|
| 방법 | 디자이너/IT가 고시 PDF 위에 **점검결과 12칸·헤더·비고·발신처**만 AcroForm 필드로 1회 얹음 → 런타임은 필드 값만 set |
| 현실성 | **중**. 1회 수작업·검수 후 자동화는 쉬움. pdf-lib `getForm()` 가능 |
| 리스크 | 폼 필드 테두리/하이라이트가 인쇄에 보이면 실패 → 외곽선 없음·인쇄 시 appearance 고정 필요; 필드 위치가 원본과 1pt만 어긋나도 육안 실패 |
| 비고 | 현 고시 PDF는 Form:none 이라 **전처리 필수** |

**비권고(명시):** satori/HTML로 “더 비슷하게” 다시 그리기 — CEO가 **실패로 정의**한 방식.

## 4. 「시각적으로 원본과 0% 차이」검수 방법 (제안)

목표: **고정 영역은 원본과 동일**, **가변 영역(채움)만** 달라도 통과.

### 4-1. 기준 이미지
- 기준: `원본_별지15_고시.pdf`를 고정 DPI(예: 150 또는 300)로 raster (`pdftoppm`)
- 비교: 동일 DPI로 출력된 **채움 후 1페이지**

### 4-2. 마스크(ROI)
| 구역 | 판정 |
|------|------|
| 고정 | 제목·표 격자·카테고리/확인사항 문구·※안내·범례 골격·확인란 외곽 → **픽셀 일치**(허용 ΔE/밝기 임계 이하, 예: 변경 픽셀 &lt; 0.5%) |
| 가변(마스크 제외) | 호·귀하·일자, 점검결과 12셀, 비고 셀, 기타사항 기입, 서명, `{아파트} 관리사무소` |

### 4-3. 그리드·항목 위치
- 12개 「점검 결과」셀의 **중심 좌표(pt)** 표를 QA 문서에 고정
- 채움 글리프 bbox가 셀 경계 안에 있는지 자동 assert
- 카테고리 병합(절연 2 / 배선 3 / 배선기구 4 / 접지 3) 행 높이 = 원본과 동일

### 4-4. 육안 체크리스트 (CEO·총괄)
1. 나란히 보기(원본 | 출력) — 격자선·점선(확인사항 구분)·여백  
2. 하단 「아파트 관리사무소」/「{단지} 관리사무소」 **잘림 0**  
3. 확인란이 원본 **오른쪽 작은 표(확인/호/담당자/인)** 인지 — 현 샘플의 「세대 확인」「담당(전기선임자)」2칸 분리형은 **레이아웃 변경**으로 실패 후보  
4. 범례가 ○(글리프)·×·`/` 인지 — CSS 원(ResultCircle)만 쓰면 원본과 다름  
5. 미방문 샘플로 `/` 셀 최소 1개 육안  

### 4-5. 참고 수치(이번 분석, 참고용)
원본 raster vs 현 샘플 page1을 동일 크기로 맞춘 뒤: 평균 절대차 ≈ 19, **차이 큰 픽셀 약 15%**.  
→ “비슷함”이 아니라 **전면 재구성**임을 정량적으로 뒷받침. (채움 마스크 전이라 엄밀한 합격 임계는 아님.)

## 6. CEO·총괄에 대한 IT 권고 (실행은 승인 후)

1. **본작업 전 아키텍처 전환**: 후보 **A(원본 PDF 배경+오버레이)** 를 기본안으로 승인 요청.  
2. satori 별지15 재구성 경로는 **폐기 또는 미리보기 전용**으로 격하.  
3. 2페이지 AI는 유지하되 **1페이지 템플릿과 완전 분리**.  
4. 재샘플 게이트: 위 4절 마스크 검수 + 미방문(`/`) 샘플 + 하단 잘림 0.
