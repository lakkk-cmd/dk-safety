# 경로 A 좌표표 (pt) — 원본_별지15_고시.pdf 기준

작성: Claude Code(로컬) / 2026-09-22 / 원본 페이지 크기 **595 x 841pt (A4)**

측정 방법: `pdfjs-dist`로 원본 PDF의 텍스트 레이어 좌표(transform matrix의 x,y)를 그대로
읽어 라벨(호/귀하/년/월/일/담당자 등) 위치를 확정하고, 그 라벨의 "앞 빈칸"에 값을 우측정렬로
채우는 방식으로 스탬프 좌표를 산출했다. 표 격자선 자체(벡터 rect)는 이번 세션에서 pdfjs
`getOperatorList()`의 인코딩을 완전히 해석하지 못해(구버전과 다른 packed 포맷) 격자선의
정확한 픽셀 좌표까지는 뽑지 못했다 — 대신 **실제 렌더링(2배율 라스터) 후 육안 대조**로
열 폭 초과 여부를 검증하고 재조정했다(아래 "실측으로 보정된 값" 참고). 코드: 좌표 상수는
`src/lib/unit-inspection-pdf-path-a.ts`에 그대로 있음(이 문서와 항상 동기화할 것).

## 실측 검증 이력 (재현용)

1. `pdfjs-dist`로 텍스트 좌표 원시 덤프 → y값 기준 행 군집화 → 열(x범위)별 재구성 —
   `scripts/_tmp-extract-coords.ts`(실행 후 삭제, 재현 필요 시 이 로직 재작성)
2. 위 좌표로 1차 스탬프 → `@napi-rs/canvas` + `pdfjs-dist`로 실제 PDF를 200% 라스터 →
   Read 도구로 육안 확인 → 비고 열 오른쪽 테두리 밖으로 텍스트 삐져나감을 발견
3. 비고 clamp를 문자수 기준(20자)에서 폰트 실측 폭 기준(33pt)으로 교체 → 재검증 → 정상

## 잔여 리스크

- 표 격자선 자체의 정확한 pt 경계(특히 비고 열 우측 테두리)는 벡터 파싱이 아니라 "실측
  렌더링 후 육안 보정"으로 간접 확인한 값이다 — 좀 더 정밀한 값이 필요하면 다른 PDF
  라이브러리(예: `pdf.js`의 다른 버전, 또는 `mutool`/`pikepdf` 등)로 벡터 좌표를 재추출해
  이 문서를 갱신할 것.
- 이 좌표는 **이 특정 원본 파일**(`public/templates/unit-inspection-form-gazette-original.pdf`,
  바이트 동일성 확인됨)에만 유효하다. 원본 파일이 재발급/재스캔되어 바이트가 달라지면
  좌표를 반드시 재검증해야 한다.
