크기 **595 x 841pt (A4)**

## 측정 방법 (7회차, 신뢰도 높음)

CEO FAIL 지적(비고 텍스트 넘침, 확인란 침범) 이후 **격자선(칸 경계) 자체의 좌표**를
직접 측정했다 — 이전(1~6회차)에는 라벨 텍스트 위치로 어림짐작했을 뿐 실제 칸 경계를
잰 적이 없었던 게 근본 원인이었다.

방법: `@napi-rs/canvas` + `pdfjs-dist`로 원본 PDF를 **4배율**로 라스터 → 특정 y(또는 x)
범위 전체에서 항상 어두운(다크) 픽셀이 나타나는 x(또는 y) 좌표를 찾는다(표 격자선은 그
구간 전체에서 항상 검지만, 텍스트는 띄엄띄엄 검다 — 다크 비율 임계값 0.85~0.9로 텍스트와
그리드선을 구분). 재현 스크립트는 세션 종료 시 삭제했으나 로직은 아래와 같다:

```
render(PDF, scale=4) → getImageData(region) →
darkFraction[x] = (해당 x열에서 r<150인 픽셀 수) / (스캔한 세로 픽셀 수)
darkFraction[x] > 0.85 인 x들을 그룹화 → 각 그룹의 중심 = 격자 세로선의 pt 좌표
(가로선은 x/y를 바꿔 동일하게)
```

**세로선** (육안 확인, 8배율):

## 객관적 넘침 검증 방법 (7회차 확립, 재사용 권장)

1. 원본 배경 위에 스탬프한 PDF를 4배율로 라스터.
2. 각 경계(테두리) 바로 바깥의 좁은 스트립(예: 우측 테두리 밖 545.5~552pt)에서
   `getImageData`로 r<150 픽셀 수를 센다 — 0이면 넘침 없음(PASS).
3. 라벨 텍스트 자체가 걸쳐 있어 오탐 우려가 있는 구간(예: 확인란 라벨 열 끝자락)은
   **원본 템플릿을 동일 좌표로 라스터한 것과 픽셀 수를 대조**해서, 스탬프본에서 픽셀 수가
   늘지 않았으면(=원본에 이미 있던 라벨 글자일 뿐) 통과로 판정한다.
