단일 Next.js 15 앱이 host 기반 미들웨어 라우팅으로 dkansim.com/hq/report/agent/contents
5개 서브도메인을 서빙한다. 저장소는 로컬 JSON과 Supabase(Postgres+Storage) 사이를 env로
전환하는 이중 모드다. Vercel에 배포되며 GitHub Actions가 CI/자동배포/자가개선 파이프라인을 맡는다.

## 핵심 사실

- 서브도메인 라우팅: `dkansim.com`(메인), `hq.dkansim.com`(`/hq`), `report.dkansim.com`(`/report`),
  `agent.dkansim.com`(`/agent`), `contents.dkansim.com`(`/contents`) — 모두 host 기반 미들웨어 rewrite.
- 저장소 이중 모드: `SUPABASE_ENABLED`(`src/lib/supabase-server.ts`), `isSupabaseReservationsDbReady()`
  (`src/lib/supabase-pg.ts`) 로컬 dev는 `data/*.json`, 프로덕션은 Supabase Postgres/Storage.
- 인증 3계통, 전부 서버 전용 쿠키: admin(`dk_admin_auth`), resident(`dk_resident_auth`, HMAC),
  worker(`dk_worker_auth`, JWT-like) — `src/lib/admin-auth.ts`, `resident-db.ts`, `worker-session-server.ts`.
- 마이그레이션은 `supabase/migrations/`에 001부터 순번으로 쌓임, `npm run db:apply`로 적용.
- 배포: **2026-08-19부로 GitHub 연동 완료, `git push`만으로 자동배포된다**(과거엔 `npx vercel
  --prod` 수동 실행이 필요했으나 지금은 아님 — 오래된 문서에 이 사실이 정정 안 된 채 남아있던
  걸 2026-09-07에 바로잡음). 배포 확인은 `npx vercel ls`로 최신 배포의 Ready 상태 폴링.
- **⚠️ Vercel Function Storage(무료 10GB) 소진 사례(2026-09-07)**: `outputFileTracingIncludes`로
  특정 API 라우트에 큰 패키지(`pdfjs-dist`+`pdf-parse`+`@napi-rs/canvas`)를 강제 포함시키면
  그 함수만 배포당 수십MB씩 새로 생성된다. 무료 플랜은 오래된 배포를 자동 정리하지 않아
  `git push` 자동배포와 겹치면 몇 달 안에 누적 한도를 초과할 수 있다(실제로 221개 배포
  ≈17GB까지 쌓였었음). 응급조치는 `npx vercel remove <project> --safe --yes`(도메인
  연결 안 된 배포 일괄삭제, 라이브 서비스 무관). 근본 해결은 해당 라우트들의 트레이싱 범위를
  줄이는 것 — 아직 미착수.
- **⚠️ Vercel 프로덕션은 로컬 파일시스템에 쓴 내용이 지속되지 않는다**(배포 이미지가 읽기
  전용). `fs.writeFile()`로 뭔가를 영구 저장하려는 코드는 로컬 dev에서는 멀쩡히 동작해서
  이 문제가 안 보인다 — 실제 사례로 백업 시스템이 이걸 몰라서 프로덕션에서 몇 달간
  아무것도 저장 안 하고 있었음(→ [[2026-확정-기술결정]] "백업/복구 시스템 전면 수정" 참고).
  영구 저장이 필요하면 Supabase Storage/Postgres를 써야 한다.

- **모바일 웹뷰/PWA 공통 함정 2가지(2026-09-07)**: (1) 다음(Daum) 우편번호 검색은 반드시
  `daum.Postcode().embed(el)`을 써야 한다 — `.open()`(팝업)은 모바일 웹뷰에서 앱과 분리된
  컨텍스트로 열려 콜백이 끊기고 뒤로가기 시 앱이 종료된다(`daum-postcode-modal.tsx`가 표준
  구현, admin-apartments-manager/apt-manager-signup에 적용됨). (2) `viewport-fit: "cover"`를
  쓰는 모든 화면의 sticky/fixed 상단바·하단바는 `env(safe-area-inset-top/bottom)` 여백이
  없으면 노치·제스처 인디케이터와 겹친다 — `home-client.tsx`가 원조 패턴, apt-manager-chrome/
  worker-chrome/hq-shell/admin-shell-critical-css에 동일 적용. 새 화면에 상단/하단 고정
  요소를 추가할 때마다 이 두 가지를 기본 체크리스트로 삼을 것.
