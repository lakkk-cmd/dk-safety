경영진 6에이전트(CTO/CSO/CMO/COO/CFO/CLO)와 3개 콘텐츠 에이전트가 `/hq` 9-에이전트 채팅으로
통합돼 있고, 별도로 "풀 에이전트"(`full-agent.ts`)가 RAG 근거표시+거짓정보 차단 채팅을 맡는다.
서버 전용 쓰기는 `AGENT_WRITE_SECRET`으로 인증한다.

## 핵심 사실

- 경영진 프롬프트: `src/lib/agents.ts`. 콘텐츠 에이전트(유튜브PD/카카오매니저/블로그에디터):
  `src/lib/content-agents.ts`.
- 9-에이전트 채팅(`/hq` 루트, `src/lib/agent-chat.ts`): `chatWithAgent()`가 `agent_chat_messages`에
  히스토리 저장, `buildBusinessSnapshot()`으로 실시간 컨텍스트 구성, RAG는 `knowledge_base`
  (`searchKnowledgeBase`, `agent-chat.ts:16`) 사용.
- 풀 에이전트(`src/lib/full-agent.ts`, `chatWithFullAgent()`): RAG는 `knowledge_chunks`
  (`searchKnowledgeChunksWithEvidence`, `full-agent.ts:38,392`) 사용 — **9-에이전트 채팅과
  다른 지식베이스를 본다.** 자세한 구분은 [[RAG-파이프라인]] 참고.
- 서버 전용 쓰기 도구(`src/lib/full-agent-tools.ts`, `/api/agent/write` 등)는 요청 헤더의
  `AGENT_WRITE_SECRET` 환경변수 값을 대조해 인증(`src/app/api/agent/write/route.ts:18`).
  이 시크릿이 GitHub Actions 시크릿에 누락되면 여러 cron이 조용히 실패한다(과거 실사례).
- 회의 스케줄: `src/lib/agent-schedule.ts` — 최초 보고 + 매주 일요일 08:00 KST 반복.
- **조직 통합 기억(2026-09-06 통합)**: `agent_memory_entries` 테이블(`src/lib/org-memory.ts`) —
  예전엔 주간회의 전용 `agent_memory`(structured_v1 JSON blob)와 9-에이전트 채팅 전용
  `agent_shared_memory`가 완전히 분리돼 있어서, 한쪽 대화에서 확정한 결정을 다른 쪽이 전혀
  모르는 문제가 반복됐다(예: 총괄디렉터 채팅에 기록한 결정을 daily-scan/주간회의가 몰랐던 실사례).
  지금은 `category`(decision/open_question/kpi/theme/meeting_summary/note) 태그를 붙인
  단일 append-only 테이블 하나를 주간회의·9-에이전트 채팅·daily-scan·SWOT분석 전부가
  공유한다. 총괄디렉터는 `remember_decision` 도구(`full-agent-tools.ts`)로 확정된 결정을
  직접 영구 기록할 수 있다 — "기억했습니다"라고 답만 하고 도구를 안 부르면 저장되지 않는다.
  `agent_memory`(구 key/content 테이블)와 `content_performance_lessons` 같은 다른 용도 키는
  여전히 별도 테이블/키로 남아있다 — 이번에 합쳐진 건 구조화 조직기억 두 개뿐이다.
- **SWOT/TOWS 분기 전략분석**(`/hq/swot`, `src/lib/swot-analysis.ts`, 2026-09-06 신설): 위
  조직 통합 기억 + `buildBusinessSnapshot()` + 최근 90일 학습신호를 근거로 Claude가
  SWOT(내부 강점·약점/외부 기회·위협) + TOWS(SO/WO/ST/WT) 전략을 생성. 분기별 크론
  + 화면 수동 재생성 버튼 둘 다로 실행 가능. 대표님 액션아이템은 홈 화면 체크리스트와
  같은 테이블(`report_action_items`)을 공유.
- **알려진 오진 2건(2026-09-06 발견·수정)**: (1) daily-scan이 "agent_reports 미승인 →
  학습 안 됨"이라고 16일 넘게 반복 보고했으나 틀린 진단(승인 여부는 콘텐츠 노출용일 뿐 학습과
  무관) — 진짜 원인은 chief 응답 maxTokens 부족(1200→6000)으로 조직기억 JSON이 매번 잘렸던
  것. (2) daily-scan이 자기 자신의 실행중 `pipeline_logs` 'started' 행을 좀비로 오인 —
  행 기록 순서를 조사 완료 후로 옮겨 해결. 두 오진 모두 daily-scan/SWOT 프롬프트에 "다시
  꺼내지 말 것"으로 명시돼 있음.
