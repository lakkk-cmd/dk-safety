**세대미방문 간이점검 UX 전면 개편 — 종이 점검표 방식으로**
- 현장 피드백: 미방문 간이점검(EPS실에서 부하전류·누설전류·절연저항만 확인)은 원래 계단으로
  층마다 이동하며 즉시 체크 가능해 종이가 더 빠른데, 앱은 세대마다 동/호/유형을 매번 다시
  입력해야 해서 오히려 느렸음.
- 재설계: 단지+동+분전함 차단기 회로수를 한 번만 입력해 고정("동 변경"/"회로수 변경" 버튼으로
  언제든 수정) → 이후 호+계량기인입선 확인+부하전류/IGR/절연저항만 있는 한 화면 반복 →
  "다음"을 누르면 그 세대가 즉시 백그라운드로 저장되고 화면은 바로 다음 호 입력으로 전환
  (응답 대기 없음).
- 대표님이 원래 요청한 "전송 버튼으로 동 단위 일괄 저장" 대신, **세대별 즉시 저장** 방식을
  제안해 채택(체감 속도는 동일, 중간에 앱이 꺼져도 이미 입력한 세대 기록은 안전). 저장 실패
  시 화면 하단 로그에서 재시도 가능. 세대방문점검 흐름은 변경 없음.
- 실제 필드 확인: 미방문 간이점검에서 수동 확인이 필요한 항목은 "계량기 인입선" 단 1개뿐
  (`SIMPLE_INSPECTION_ITEM_IDS ∩ MANUAL_CHECK_ITEM_IDS`), 나머지는 자동판정 — 이 사실이
  한 화면으로 합치는 설계의 근거가 됨.
- **실제 워커 계정으로 클릭 테스트는 안 함** — 법적 서류(직무고시 점검표)라 발급 트리거 후
  수정 불가 트리거가 걸려있어, 로그인 정보 없이 임의 계정 만들거나 세션 위조하는 걸 피함.
  빌드 통과+코드 로직 검토로만 검증, 현장 재확인 대기.

## 알게 된 것
- 카카오 "나에게 보내기" 메모 API는 카카오 개발자 콘솔에 등록된 도메인 외의 `web_url`을
  전부 무시하고 등록 도메인 기본값으로 치환한다 — 완전히 무관한 외부 URL로도 재현되는
  현상이라 서버 라우팅/미들웨어 문제로 착각하기 쉽다. 등록 도메인 경유(`/go?next=`) 우회가
  유일한 해결책. 앞으로 카카오 메모에 새 링크를 추가할 땐 반드시 이 패턴을 거쳐야 함.
- 다음(Daum) 우편번호 검색 API는 모바일 웹뷰/PWA에서 `.open()`(팝업) 대신 반드시
  `.embed()`(같은 페이지 내 렌더링)를 써야 한다 — 팝업은 앱과 분리된 컨텍스트로 열려 콜백
  단절+뒤로가기로 앱 종료라는 두 가지 실제 버그를 동시에 유발한다.
- Next.js 15의 `npm run build`(`npm run clean` 포함)는 `.next-dev`를 함께 삭제한다 — 로컬
  dev 서버가 떠 있는 상태에서 build를 돌리면 dev 서버가 500 에러를 내며 죽는다. 매번 재시작
  필요(이번 세션에서 5회 이상 반복 발생, 앞으로 build 전에 dev 서버 종료 여부 먼저 확인할 것).
- Vercel 배포 URL 하나마다 함수 크기가 다 달라, `outputFileTracingIncludes`로 특정 라우트에
  큰 패키지를 강제 포함시키면 그 함수만 수십MB씩 배포마다 반복 생성된다 — 오래된 배포를
  자동 정리 안 하는 무료 플랜에서는 이게 누적되어 저장공간을 소진하는 실제 원인이 될 수 있음.
